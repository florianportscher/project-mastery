# Case archive

**Context.** Map builds and Chats on staging are analysed to find what the prompts get wrong, but the evidence does not last: `staging-reset-map` or a deleted Course removes the build, Langfuse keeps model calls for 30 days on the free plan, and nothing recorded which app version made a build. Two analyses of one Course confused runs from different commits. What is kept comes from real course Materials, so it must stay out of the public repo.

**Decision.** A run worth analysing is kept as a case: one folder `cases/<case id>/` in the private repo `project-mastery-cases`, outside this repo's tree (`MASTERY_CASES_DIR`). `pnpm archive course <courseId> [--note "…"]` writes the Course's current map build and `pnpm archive chat <chatId>` a Chat (its messages, its Course's build snapshot and the calls of its session), and pushes it straight to that repo's `main`: it is data, not code, so it takes no PR. The case id is `<date>-<map|chat>-<n>`. The bundle is a `manifest.json` (kind, Course name, the Materials' shape, the run's UTC times, the app commits and models of its calls, cost, the note, the calls missing from Langfuse and a list of observations), `run.json.gz` (the build snapshot `agent inspect` reads, with every chunk's Markdown) and `calls.jsonl.gz` (each model call's full input and output, page images replaced by the Material's sha256 and page). The Material files go to `MASTERY_MATERIALS_DIR` as `<sha256>.<ext>`, in neither repo. Before writing, the archive checks that the cases repo's `origin` is private and that both folders lie outside this repo, and refuses otherwise. `pnpm archive flagged` archives every `developer_flags` row without a `case_id` (a Chat or map build a developer sent from the app) with its note and sets the row's `case_id` through `writeStaging` ([ADR 0029](0029-agent-writes-to-staging.md)); a map flag is refused when the Course was rebuilt since. `agent staging-reset-map` archives first and deletes nothing when the archive fails. Every model call and every build records the app commit it ran on (`appCommit` in Langfuse metadata, `knowledge_map_builds.app_commit`), so a case names the versions it shows. Observation issues name the case id and call ids in their **Seen on** lines.

**Consequences.** A run can be read and later replayed after its Course and its Langfuse traces are gone, and its labels say which commit and model made it. A case older than 30 days keeps the calls Langfuse still had; the manifest counts the missing ones. Each archive costs Langfuse reads only, no model calls. The cases repo grows with every case; a bundle is compressed, and the PDFs are stored once per file. Layout and commands: [docs/agents/cases.md](../agents/cases.md).
