## Rules added and issues filed

No rule added. The spec review asked whether knip catches an exported type that only its own file uses. It does not: knip skips an export whose type appears in an exported signature of the same file (probed: a type used in an exported function's parameter is silent; a type used only in a private variable is reported as an unused exported type). All 28 types were of the first kind, which is why knip stayed at 0. `ignoreExportsUsedInFile` only silences more, so catching this would take a custom ESLint check, which is not worth it for a one-time cleanup.

Reviews: Spec axis had one finding (the rule above), resolved as described. Standards axis had none: no unexported type is imported elsewhere.
